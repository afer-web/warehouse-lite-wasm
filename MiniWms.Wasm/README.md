# MiniWMS.Wasm — Industrial lite-WMS running fully in the browser

MiniWMS is a **minimal, production-minded warehouse reference app** packaged as a **standalone Blazor WebAssembly** experience backed by **SQLite WASM (sql.js)**.  
There is **no backend, no SaaS telemetry, no cloud database** — only static assets, optional OPFS snapshots, IndexedDB failover, and `localStorage` preferences.

```
┌─────────────┐      ┌───────────────┐       ┌─────────────┐
│ Blazor WASM │ ---> │ sql.js WASM   │ --->  │ Stocks view │
└─────────────┘      └───────────────┘       └─────────────┘
         │                     │
         v                     v
IndexedDB blob          OPFS (/miniWms/database.sqlite)
```

## Highlights

| Area | Notes |
| ---- | ----- |
| **Articles** (`Items`) | Full CRUD (Code, Description, Unit, UTC `CreatedAt`) |
| **Locations** (`Locations`) | Warehouse bins (`Code`, `Area`, `Description`) |
| **Movements** (`Movements`) | Load / unload ledger with validations |
| **Inventory** (`Inventory`) | Non-zero balances across `(Item × Location)` |
| **Dashboard** (`/dashboard`) | KPI cards, telemetry table, CSS + ASCII ladders |
| **Persistence** | SQLite file bytes persisted to OPFS worker + IndexedDB mirror |
| **Preferences (optional)** | `localStorage` helpers in `miniWmsPreferences.js` — wire from C# if needed later |
| **Styling** | Dark industrial shell, neon CTAs, responsive sidebar |

Triggers keep `Stocks` synchronized whenever a row inserts into `Movements`, while C# rejects illegal unload quantities before hitting SQLite.

---

## Tech stack

- **Runtime**: .NET **8**
- **UI**: Blazor **WebAssembly** + component model
- **Storage engine**: SQLite compiled to WASM via **`sql.js@1.11`**
  - WASM binary vendored into `wwwroot/sqlite/sqlite-wasm.wasm`
  - Loader script `sql-wasm.js` (global `initSqlJs`)
- **Browser APIs**: **OPFS**, **IndexedDB**, **Dedicated Worker** (`js/opfsWriteWorker.js`)

> ℹ️ **Entity Framework Core** cannot host the canonical native SQLite provider inside the mono WASM sandbox. MiniWMS instead uses a narrowly scoped `DatabaseService` façade over deterministic SQL helpers.

## Getting started — restore sql.js bits

sql.js binaries are fetched through npm to respect vendoring/licensing while remaining fully offline afterward.

```powershell
cd MiniWms.Wasm
npm install            # executes tools/copy-sqlite.mjs automatically
dotnet build           # restores NuGet packages
```

Artifacts land in:

- `wwwroot/sqlite/sql-wasm.js`
- `wwwroot/sqlite/sqlite-wasm.wasm`

## Local development workflow

Use the WASM dev server (hot reload compatible):

```powershell
dotnet watch run --project MiniWms.Wasm.csproj
```

Navigate to `https://localhost:7xxx` — the SPA bootstraps `miniWmsDb.ensureReady()`, provisions schema, restores snapshots.

## Static publishing & “open index.html” expectations

Produce a trimmed static bundle:

```powershell
dotnet publish MiniWms.Wasm.csproj -c Release /p:PublishDir=artifacts/publish -o artifacts/publish
```

The deployable roots live under **`artifacts/publish/wwwroot/`**:

- **`index.html`**
- `_framework/` (dotnet.wasm payloads)
- `sqlite/` WASM assets & bridge scripts

### Serving statically

Browsers disallow most `fetch` flows from raw `file://` URIs once Blazor pulls `_framework/*.wasm`.  
Prefer any static host rooted at `./wwwroot`:

```powershell
cd artifacts/publish/wwwroot
python -m http.server 8787 --bind 127.0.0.1
```

Open `http://127.0.0.1:8787/` (not raw `index.html` on disk) for first-class OPFS access + wasm streaming.

Compression artifacts (`*.br`, `*.gz`) may appear — production hosts usually serve `.br/.gz` with proper `Content-Encoding` or fall back seamlessly to uncompressed peers.

Install the optional toolchain for tighter bundles:

```powershell
dotnet workload install wasm-tools
```

## Security & data hygiene

- Data never leaves the device unless the user exports files manually.
- Foreign keys are enforced (`PRAGMA foreign_keys = ON;`).
- Deletes respect SQLite constraints — surfaced as Blazor alerts when conflicts occur.

### Maintainer notes

When adjusting schema, bump the JS migration snippet inside `miniWmsDb.js` carefully — clients rely on deterministic creation order. Persisted snapshots regenerate automatically whenever rows mutate (debounced 120 ms).
